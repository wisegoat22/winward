# Winward v4: learn the necessary step and preserve earlier skills

V4 addresses two measured v3 failures: deferring on reachable uncertainty tasks and forgetting earlier graph and changed-goal skills. The previous v3 audit is now development evidence. V4 reserves new final instances and freezes its training choices before evaluating them.

This remains a small structured decision policy trained on an Apple silicon Mac. It is not a 4B language model. Possible worlds, probabilities, candidate actions, costs, and action effects are supplied. The model does not infer those facts from arbitrary prose or generate code.

The architecture is unchanged from v3: **4,862,721 parameters**, with six shared transformer layers and 505 numeric input features per candidate. Both training candidates initialize from our own v1 checkpoint. No Qwen weights, outputs, language embeddings, cloud training, or paid API calls are used.

## What changes

Training includes combinations of preparation, diagnosis, uncertain requirements, noisy observations, reversible failures, and changed goals. Preparatory actions can be valuable even when they make no immediate progress on the goal. Training also includes legitimate cases for stopping or requesting information, so the desired behavior is not simply “always act.”

Replay retains the earlier training sources. Correct teacher preferences come from our own frozen v1 on legacy tasks and v2.1 on goal changes and observed tool states. Incorrect teacher decisions are not required targets. An additional success-regret loss penalizes preferring actions whose declared achievable success is below the teacher's best. It uses conditional probabilities among candidates with exact value labels; pruned actions without those labels are excluded from this auxiliary loss. Cross-entropy still covers every eligible choice. These search-derived values are training labels only and never enter the inference features.

The shared policy still chooses its own action. There is no search correction, hidden-world input, or automatic replacement of an unsuccessful learned choice with a baseline's answer. Permission, applicability, and verified-stop checks remain explicit rules.

## Experiment controls

Two settings are declared before training: correct-teacher mixing of 60% with learning rate 0.00005, and 80% with learning rate 0.00003. Each has a fixed 10,000-step budget, batch size 128, and validation every 500 steps. The belief success-regret coefficient is 4.0. Sampling probabilities are 40% legacy, 20% goal changes, 10% tool observations, and 30% uncertainty.

There are **160,000 training rows**: 48,000 legacy rows, 32,000 goal/cost rows, 32,000 observed tool-state augmentations, and 48,000 new belief rows. These are not 160,000 independent coding tasks. Both runs use the same training data. The [sealed training plan](../reports/v4/training-protocol.json) records the budget, initialization hashes, and source hashes before training. Preparation and both runs took 355.35 seconds on this Mac; this is a single local timing observation.

Checkpoint selection uses validation only. All strict retention checks take precedence over uncertainty performance. If every candidate fails retention, the result remains failed even when another metric improves. The final audit cannot select another checkpoint or trigger tuning against the same final cases.

The [audit protocol](../reports/v4/audit-protocol.json) preserves the prior twelve promotion checks. It uses 240 uncertainty problems with four sampled episodes each, 300 rollouts in each of two graph suites, 200 changed-goal pairs, and 40 actual coding fixtures. Comparisons with v3 are diagnostic; promotion still requires retaining the stronger older baselines and matching both cheap uncertainty rules.

Token and action-time costs in uncertainty tasks are declared estimates. Policy decision time is measured. Weighted cost is declared tokens plus 0.01 times declared action milliseconds and measured decision milliseconds. Lower costs on episodes completed by both methods cannot compensate for failed completion gates. Four sampled episodes from one problem are dependent observations, not four independent tasks.

### Final audit: improved uncertainty, no promotion

The [one-time final audit](../reports/v4/evaluation.json) passed **seven of twelve checks**. The selected weights and dependency sources remained unchanged, and no test outcome changed the checkpoint selection or training settings.

On those 773 jointly successful episodes, declared action costs plus measured decision overhead were **18.8% lower** than information-first rules. This is a weighted simulation-cost result, not a measured reduction in API token bills or a claim of faster neural inference. The model's decisions took longer than the cheap rules' decisions. Legacy action costs also worsened, so the uncertainty improvement cannot establish a general efficiency advantage.

The 240 uncertainty problems contain 20 cases from each of 12 composition anchors. Twenty begin already verified; twenty have no modeled path to success within five actions. Both remain in all aggregate comparisons. Exact contingent search reaches **89.11% expected completion**, placing v4 about **0.51 percentage points** below the declared-model ceiling. Sampled completion can exceed that exact expectation through sampling variation. Neither result estimates reliability on arbitrary real-world tasks.

### What improved, and what did not

Frozen v3 completed **406/960 (42.29%)** on these same fresh v4 uncertainty episodes, against v4's **856/960 (89.17%)**. On preparation chains requiring five actions, v3 completed 0/80 and v4 80/80; on prepared diagnosis, v3 completed 0/80 and v4 79/80. These are matched comparisons under the new distribution. Comparing v4's 89.17% directly with v3's earlier published 61.04% would mix different task distributions.

V4 also improved matched legacy completion over v3 (294 versus 291 of 300) and new graph combinations (275 versus 271 of 300). However, changed-goal decisions **regressed even against v3**: 369 versus 376 correct out of 400, with 170 versus 176 fully correct pairs out of 200. The stronger v1/v2.1 retention requirements remain unmet. Improvements are not uniform across uncertainty anchors either: known-cause expected completion was slightly below the cheap rules.

All four methods completed the 40 controlled coding fixtures. Mean wall time was 81.67 ms for v4, 78.88 ms for v3, 79.62 ms for v2.1, and 57.60 ms for evidence-first rules. The fixtures execute supplied patches and real acceptance checks; the model does not generate patches or operate on unfamiliar repositories. Timing comes from one shared Mac session and is not a precision benchmark.

V4 remains available as an experiment. V1, v2.1, and v3 are retained; no old task is silently routed to v4. The broader goal of improving uncertainty decisions **while preserving every earlier capability** has not been achieved.

## Reproduce on Mac

Use the pinned environment and retained v1/v2.1 runs described in [the v3 guide](V3.md#reproduce-on-mac). Preserve existing runs. Training, validation, weights, and final audit artifacts are stored locally under `runs/` and excluded from Git.

The audit also needs the frozen v3 run for its diagnostic comparison. On a fresh checkout, follow the complete v3 reproduction first. From the repository root:

```sh
uv sync --frozen
.venv/bin/python -m agent_training.evaluate_v4 \
  --run runs/goalpolicy-v4 --declare-protocol
.venv/bin/python -m agent_training.train_v4 \
  --output runs/goalpolicy-v4 --declare-plan
.venv/bin/python -m agent_training.train_v4 \
  --output runs/goalpolicy-v4
.venv/bin/python -m agent_training.evaluate_v4 \
  --run runs/goalpolicy-v4
.venv/bin/python scripts/server.py start
```

Open [the v4 lab](http://127.0.0.1:8765/v4) for all audit checks and eight hand-written demonstrations. The demonstrations are separate from the audit and do not run real tools. The earlier interfaces remain at `/policy`, `/v2`, and `/v3`.

Use an unused output directory. Both declarations refuse overwrite. Training requires that directory to contain only the two sealed protocols, and checks that source code and initialization weights still match the declaration. If saving training output to a log, place the log outside that directory until training finishes. An interrupted run is retained; the final audit also refuses repeat execution.

Reusing published seeds is reproduction, not a new blind evaluation. Future experiments must reserve new final cases and declare their complete protocol before training. More parameters alone do not establish reliable decisions or fix an incomplete model of the world.
