# Winward v3: a shared policy for known and uncertain outcomes

V3 trains one policy to choose actions from deterministic task state or a public distribution over possible states. Its training combines earlier planning skills, goal changes, observed tool failures, and uncertainty examples. A strict promotion gate checks whether those additions preserve earlier capabilities and improve useful efficiency.

The candidate has **4,862,721 parameters (4.86 million)**. It continues training from **our own v1 checkpoint**, which originally started from random weights. V3 itself is not a new random initialization. No third-party pretrained weights, Qwen outputs, language embeddings, or paid model calls are used. This is **not a 4-billion-parameter model**.

The frozen candidate failed one strict validation-retention check and **eight of twelve final promotion checks**. It remains experimental; existing defaults are retained. Better performance on one suite cannot cancel a regression elsewhere. The final audit was separate from training and did not select another checkpoint.

## What the model sees and chooses

The model receives numeric descriptions of the current goal, possible states, available actions, permissions, prerequisites, effects, observations, and token/time costs. It ranks the supplied actions, including finish and request-information candidates. It does not read arbitrary natural-language instructions, discover a world model, write a patch, or invent a tool.

Deterministic observations support up to 12 Boolean facts and 10 actions. Belief observations additionally support up to **four live hypotheses** and **two outcomes per action per world**. Larger belief inputs are rejected rather than silently truncated. Every hypothesis and transition probability is supplied to the model. The actual sampled hidden world is not an input.

Belief features represent observation equivalence: which possible outcomes produce the same observation. They include supplied transition probabilities and one-action summaries such as expected goal progress and information gain. These summaries are computed by code from public inputs. They are not learned predictions or a five-step search result. World IDs, observation spelling, action IDs, prose, family labels, teacher answers, and provenance do not enter the feature vector.

The policy has six shared transformer layers, width 256, eight attention heads, and one shared output head. Its **505 input features per candidate** are:

| Channels | Count | Meaning |
| --- | ---: | --- |
| Existing graph observation | 103 | Unchanged v1 encoding for deterministic graphs and actual tool observations |
| Public belief observation | 400 | Possible states, probabilities, declared outcomes, observation partitions, and one-action summaries |
| Observation-format flags | 2 | Graph or belief input |

The unused block is zero for each format. V1's existing weights are copied; additional input-projection columns start at zero. Graph logits therefore match v1 before continued training, within floating-point tolerance. All layers then participate in training. This is one model, without separate domain experts, an ensemble, or an exact-planner correction at inference.

There is no positional encoding. Action reordering should reorder scores rather than define the answer. Permissions, current applicability, and verified-stop requirements are enforced by code. Their enforcement must not be credited as learned judgment. Softmax preferences are not calibrated probabilities of success.

## Decision objective and five-step consequences

The synthetic teachers prioritize the stated win, then minimize expected weighted token/time cost, then the number of actions. Belief planning follows possible observations and their posterior states for up to five actions. Its win is **verified completion inside the supplied model**: the goal holds in every remaining possible state. Supplied probabilities or effects can still be wrong about a real system.

Exact contingent search supplies synthetic training labels. Search that exhausts its node budget is not accepted as a complete label. The learned policy imitates the next decision; it does not run guaranteed five-level reasoning internally. Evaluation follows its own choices, receives an observation, updates state, and asks it for the next action without an oracle correcting mistakes.

Goal changes replace the current objective in the input. Earlier work can become irrelevant or require rework. Names, emotional framing, and unrelated prose are omitted by construction. This exclusion does not establish natural-language understanding or an ability to distinguish relevant prose from noise.

## Training and preservation of earlier skills

The run contains **104,000 training rows**:

| Source | Rows | Probability of sampling a training row from this source |
| --- | ---: | ---: |
| V1 training graphs and trajectory states | 48,000 | 37.5% |
| Existing v2.1 synthetic goal/cost curriculum | 16,000 | 18.75% |
| Existing v2.1 observed tool-state augmentations | 16,000 | 18.75% |
| New belief decisions and posterior states | 24,000 | 25% |

Rows are not independent real coding tasks. Tool rows are sampled from existing permutations of actual training observations. Their targets come from the observed-state evidence-first teacher, with indistinguishable unverified patches tied. Hidden patch correctness does not determine the target. The code harness executes supplied candidate patches and acceptance checks; the model does not generate code.

Belief training covers diagnosis, missing requirements, known causes, unreliable tools, and noisy evidence. Data includes teacher-plan prefixes, exploratory observable branches, changed goals, and shrinking remaining horizons. Validation uses reserved compositions and independent seeds. No actual hidden world is retained in a training observation.

For legacy training rows where v1's top choice agrees with an exact label, the target mixes 85% exact-label probability with 15% v1 soft preferences. If v1's choice is wrong, no distillation is applied to that row. This encourages retention without requiring imitation of known mistakes. Validation rows and final audit instances never enter the training batches.

The run used 6,000 AdamW steps, batch size 128, initial learning rate 0.0001 with warmup and decay, and gradient clipping. Recorded preparation and training time was **108.78 seconds** on the local Mac. Timing is a single run, not a hardware benchmark. Validation ran every 500 steps.

The predeclared selector first requires every strict retention gate to pass. If none do, it chooses the smallest worst regression and marks the candidate as failed. After retention, it considers expected belief completion and belief teacher agreement. It does not silently loosen the gate or select using final test results.

## Final audit protocol

The [sealed protocol](../reports/v3/audit-protocol.json) compares frozen models on matched fresh instances:

- 120 uncertainty problems, with exact expected outcomes and four sampled episodes each.
- Two graph suites of 2,400 rows and 300 completion rollouts each.
- 200 paired changed-goal cases, compared against v2.1.
- 40 actual coding fixtures, compared against v2.1 and cheap rules.

Every retention gate must pass. V3 must also match both cheap uncertainty baselines on expected and sampled completion, and improve total cost against the strongest cheap baseline on the same episodes both methods complete. Efficiency comparisons exclude neither model's failures silently: completion is gated separately, and paired-success cost is identified explicitly. Failing any gate preserves existing defaults.

The uncertainty baselines are one-step immediate-progress and information-first rules. They see the same public model but do not perform recursive search. Evaluation records a separate exact-planner reference where applicable; it never substitutes the reference's action for the neural choice.

**Declared costs and measured time are different.** In belief simulations, action-token costs and action latencies are supplied estimates. The policy's decision time is measured locally. The efficiency gate uses:

```text
declared tokens + 0.01 × (declared action milliseconds + measured decision milliseconds)
```

Those weights are a declared experiment preference, not a universal exchange rate. Belief simulations do not measure real tool execution time. The actual fixture harness separately measures wall time, decision time, and execution results. Neural selection generates zero language tokens.

An initial protocol was sealed before training. A coverage review amended it **after training and checkpoint selection but before any final audit instances or outcomes**. The amendment added explicit goal-change retention, paired-success legacy action-cost retention, and enforcement of the existing validation-retention requirement. Weights, selection, and validation outcomes did not change. The [amendment record](../reports/v3/protocol-amendment.json) preserves both protocol hashes and the reason; the [original protocol](../reports/v3/audit-protocol-v1.json) remains available. Future experiments must seal the full protocol before training.

### Final audit results: not promoted

The [independent audit report](../reports/v3/evaluation.json) records **eight failed checks out of twelve**. V3 completed more tasks in the new graph-composition suite and retained actual fixture completion. It lost legacy completion and changed-goal accuracy, and both cheap uncertainty rules completed substantially more tasks.

| Promotion check | Frozen v3 | Matched reference | Result |
| --- | ---: | ---: | --- |
| Existing validation-retention requirement | One component failed | All components must pass | **Fail** |
| Legacy goal completion | 282/300 (94.0%) | V1: 293/300 (97.67%) | **Fail** |
| V2-composition goal completion | 274/300 (91.33%) | V1: 254/300 (84.67%) | Pass |
| Legacy declared action cost, same 282 jointly completed tasks | 1,337.70 | V1: 1,345.89 | Pass |
| Changed-goal next-action accuracy | 91.5% | V2.1: 96.5% | **Fail** |
| Changed-goal pairs with both choices correct | 167/200 | V2.1: 187/200 | **Fail** |
| Actual fixtures verified and finished | 40/40 | V2.1: 40/40 | Pass |
| Expected uncertainty completion versus immediate-progress rules | 60.47% | 92.62% | **Fail** |
| Sampled uncertainty completion versus immediate-progress rules | 293/480 (61.04%) | 438/480 (91.25%) | **Fail** |
| Expected uncertainty completion versus information-first rules | 60.47% | 92.98% | **Fail** |
| Sampled uncertainty completion versus information-first rules | 293/480 (61.04%) | 444/480 (92.5%) | **Fail** |
| Belief total weighted cost, same 285 jointly completed episodes | 16.77 | Information-first: 35.30 | Pass |

The two passing cost comparisons cover only the stated **jointly successful subsets**. They do not establish an overall efficiency advantage: v3 failed many more uncertainty tasks and also lost legacy wins. Expected uncertainty completion integrates the declared probability trees; sampled completion uses four episodes per problem. Neither is a real-world reliability estimate.

Evidence-first rules also completed all **40/40 actual coding fixtures**. Mean wall time was 86.15 ms for v3, 83.77 ms for v2.1, and 60.26 ms for evidence-first rules; mean action counts were 9.55, 9.45, and 9.45 respectively. V3 did not demonstrate a useful advantage on these fixtures. These times are one local audit on shared hardware, not an isolated throughput benchmark.

The checkpoint hash stayed unchanged throughout the audit. No audit result changed its weights or selected step. Full validation history and training provenance are in the [training report](../reports/v3/training.json). The current milestone—one policy that retains prior skills and beats cheap uncertainty rules—has not been achieved.

## Reproduce on Mac

The public repository is [wisegoat22/winward](https://github.com/wisegoat22/winward). `runs/`, checkpoint weights, and generated datasets are local artifacts excluded from Git. Run these commands from the repository root using the pinned environment:

```sh
uv sync --frozen
```

V3 requires v1's checkpoint and training/validation rows, plus v2.1's checkpoint and training/validation rows. If those runs already exist, preserve them and skip their training commands. On a fresh checkout, create them with:

```sh
.venv/bin/python -m agent_training.train \
  --output runs/goalpolicy-v1 \
  --train-cases 48000 --valid-cases 2400 --test-cases 2400 \
  --steps 5000 --seed 20261001 --trajectories --select-rollout

.venv/bin/python -m agent_training.train_tools \
  --output runs/goalpolicy-v2-tools
```

The historical v1 trainer also writes its original test split. V3 training does not read that split or prior evaluation reports. It reads only the permitted training/validation files and frozen baseline weights.

For v3, seal the protocol first, train without generating final audit instances, and audit the frozen checkpoint once:

```sh
.venv/bin/python -m agent_training.evaluate_v3 \
  --run runs/goalpolicy-v3 --declare-protocol

.venv/bin/python -m agent_training.train_v3 \
  --output runs/goalpolicy-v3 \
  --v1-run runs/goalpolicy-v1 --tools-run runs/goalpolicy-v2-tools \
  --steps 6000 --belief-cases 24000 --belief-valid-cases 1200 \
  --seed 300000000 --batch-size 128 --learning-rate 0.0001

.venv/bin/python -m agent_training.evaluate_v3 \
  --run runs/goalpolicy-v3 \
  --v1-run runs/goalpolicy-v1 --tools-run runs/goalpolicy-v2-tools

.venv/bin/pytest -q
```

Use an unused run directory and keep the same path across all three v3 commands. Protocol sealing refuses overwrite. Training accepts an empty directory or one containing only its sealed `audit-protocol.json`; an existing completed or interrupted training run is preserved. The audit also refuses to repeat once it has started. Do not delete its marker to select a favorable rerun.

Reusing these published seeds reproduces the experiment; it is not a new blind evaluation. A new experiment needs a new run directory, fresh reserved evaluation instances, and its complete immutable protocol before training. Hardware and library floating-point differences can change learned weights even with fixed data seeds. Report new hashes and all outcomes.

The new checkpoint does not automatically replace v1 or v2.1. Local serving and promotion must follow the audit gates.

Start the local app with `.venv/bin/python scripts/server.py start` and open [the v3 lab](http://127.0.0.1:8765/v3). The page displays every promotion check, compares learned choices with search, and lets the model act in the existing demonstration situations. Demonstration outcomes are separate from the frozen audit. Stop the app with `.venv/bin/python scripts/server.py stop`.

## Boundaries

Fresh instances are generated from developer-known task families and fixture templates. This is not an unfamiliar-repository benchmark, natural-language benchmark, or evidence of reliable decisions in arbitrary real situations. Four modeled possibilities do not capture unrestricted real-world uncertainty. The supplied model can omit an important outcome or assign it the wrong probability.

The actual coding harness writes trusted generated fixtures into disposable directories and runs fixed acceptance checks. It is not an operating-system security sandbox and must not execute arbitrary untrusted code. No user repository is edited by these experiments.

V3's purpose is to test whether a small shared policy can learn uncertainty decisions while preserving useful earlier behavior. Increasing parameter count does not, by itself, fix missing observations, inaccurate transition models, forgetting, or decision overhead.
